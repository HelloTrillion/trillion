# Routines: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A timed ask can be a routine: it runs unattended, builds a board in today's day conversation or its own, tells the user in one quiet line when it is ready, stays silent with nothing to say, and is edited by feedback.

**Spec:** `docs/specs/2026-10-27-routines.md` (read it, and `docs/specs/2026-10-26-your-day.md`, `docs/specs/2026-10-25-live-widgets.md`, `docs/design/widgets.md`).

**Architecture:** `schedules` gains a target, a conversation, notes, pause and a failure count (migration 014). The runner hands a routine to the `Asker` with its target conversation; the router learns `via="routine"`, which allows the board tools only on that conversation. A board writes a `'ready'` notice through the door; `routine_nothing` ends a run silently. `routine_narrow` and `routine_widen` edit the notes. The page shows the ready line with Open, an unread mark, and a Routines group in Settings.

**Tech stack:** Python 3.13 (uv, pytest, ruff, strict mypy); TypeScript (Vite, vitest, jsdom).

**Branch:** `routines/spec` (holds the spec; build on it).

**House rules:** `git commit -s`, message ending in a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; only `git add` your files; generic names only (`scripts/containment_check.py`); short plain comments that say why; never play sound; no browser.
