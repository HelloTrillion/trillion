# Her board: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trillion can put typed widgets on a board in the workspace, change and remove them, and the board is saved with its conversation.

**Spec:** `docs/specs/2026-10-25-her-board.md`. Read it first; it holds the kit's fields and limits, which this plan does not repeat.

**Architecture:** A pure Python module validates and edits boards (`workspace/board.py`). A store saves one board per conversation. A small service applies a change, saves it, and broadcasts `board{board}` to the pages on that conversation. Four tools call the service. The session sends the board on start, takes the page's edits, and adds a one-line summary to the volatile context. On the web, `chart.ts` (pure SVG maths) and `board.ts` (DOM) draw it in the workspace.

**Tech stack:** Python 3.13 (uv, FastAPI, aiosqlite, pytest-asyncio, ruff, strict mypy); TypeScript (Vite, vitest).

**Branch:** `workspace/her-board` (on top of `ui/workspace-button`, which added the sidebar's Workspace button).

**House rules:** `git commit -s`, message ending in a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; only `git add` your files; no real people or businesses (`scripts/containment_check.py`); short plain comments that say why; never play sound in a browser. Checks: `uv run pytest -q`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy`, `python3 scripts/check_one_writer.py`, `python3 scripts/containment_check.py`, `python3 scripts/check_raw_hex.py`, `python3 scripts/check_agent_name.py`; web `pnpm -C apps/web test && pnpm -C apps/web typecheck && pnpm -C apps/web build`.

### Task 1: The kit (`src/trillion/workspace/board.py`)

**Files:** create `src/trillion/workspace/__init__.py`, `src/trillion/workspace/board.py`, `tests/workspace/__init__.py`, `tests/workspace/test_board.py`.

A pure module, no I/O.

- [ ] Write failing tests first, covering:
  - each widget type accepted with minimal and full fields; `size` defaulting to `medium`; strings trimmed and capped per the spec;
  - every limit refused with a message naming the widget and the problem: unknown type, 13th widget, 6 series, a series length not matching `x`, NaN/inf values, donut with 2 series, table row length, note over 2000, timeline time not `HH:MM`, compare with 1 or 5 options, score outside 0–10, `pick` not an option's name;
  - board edits: `show(board, title, widgets, mode)` replace and add (ids `w1…` from `next_id`, never reused after removals), `update(board, id, widget)` keeps id and position, `remove(board, ids | "all")` (removing the last widget closes the board), `close(board)`, reopening with `show` and no widgets;
  - `summary(board)` → `Board (open): "October spend": w1 stat "Total", w2 line chart "Daily spend".` with titles clipped to 40 and `Board (closed): …` when closed, `""` for none.
- [ ] Implement with frozen dataclasses or plain dicts plus validator functions, whichever reads cleaner; raise one `BoardError(message)` with the first problem. Keep the JSON shape of the spec exactly (it goes to the page as is).
- [ ] Run the tests, ruff, mypy; commit "Workspace: the widget kit and board edits".
