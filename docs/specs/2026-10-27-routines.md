# Routines

**Date:** 2026-10-27 · **Requirements:** AGT-3, AGT-6, AGT-7, AGT-8, SUR-9 · **Builds on:** `docs/specs/2026-10-26-your-day.md`, `docs/specs/2026-10-25-live-widgets.md`, the scheduler (timed asks, AGT-9)

"Every weekday at 8, build my day." "Every Monday morning, show me last week's
revenue." A routine is a timed ask that builds a board. It runs while nobody is
watching, puts its result in a conversation of its own (or in today's day
conversation), and tells the user it is ready in one quiet line. With nothing worth
saying it says nothing. Feedback in its conversation edits what it looks at next time.

## Decisions

| | Decision | Why |
|---|---|---|
| D1 | **A routine is a timed ask with a target.** Same table, same runner, same card to set it up, same missed and failed handling. | What exists already is the scheduler routines need; a second one would drift. |
| D2 | **Where it lands.** A day routine fills today's day conversation. Any other routine owns one conversation, titled with its name, and each run replaces its board. | What the user chose. |
| D3 | **Telling the user.** One line ("Your Monday revenue is ready") with an Open button, through the door like any notice, so it is spoken once when voice is on and the page is free, and shown otherwise. Nothing to report: no notice, a log line only (AGT-6). | What the user chose. |
| D4 | **Managing.** Set up by asking (a card, as timed asks). Settings lists routines with their next run, pause and resume, and delete. In a routine's conversation, feedback edits its notes: narrowing at once, widening on a card (AGT-7). | What the user chose. |
| D5 | **Board tools, unattended, only here.** A routine run may use `workspace_show`, `workspace_update` and `workspace_remove`, and only on its own target conversation. Every other unattended run still gets no board tools, and `day_open` is never offered. | A board with nobody watching is safe when it can only be the routine's own. |

## What a routine is

- Migration `014_routines.sql` adds to `schedules`:
  - `target TEXT` (`NULL` for a plain timed ask; `'day'`, or `'own'`);
  - `conversation_id TEXT` (an `'own'` routine's conversation, made on its first run);
  - `notes TEXT NOT NULL DEFAULT ''` (what to watch and what to leave out, edited by feedback; at most 1,000 characters);
  - `paused_ms INTEGER` (paused when set; due times are not moved on while paused);
  - `failures INTEGER NOT NULL DEFAULT 0` (failed runs in a row).
  - And allows notice kind `'ready'` (the notices table is rebuilt, as earlier migrations did).
- Conversations gain kind `'routine'` (an `'own'` routine's conversation), titled with the routine's name and never renamed by naming.
- `ask_schedule` gains an optional `routine` argument: `"day"` or `"own"`. The card says it: "Every weekday at 8:00 am: build my day (a routine, on Your day)". The prompt tells her to set `routine` when the user asks for something to be built or shown regularly, `"day"` when it is about their day.

## A run

- The runner hands a routine to the same `Asker`, with its target. The run's conversation is today's day conversation (made if missing) for `'day'`, or the routine's own (made on the first run) for `'own'`.
- **Tools:** the unattended view, plus the three board tools. The router learns `via="routine"`: everything `via="schedule"` refuses it refuses too, except the board tools, which it allows only when `ctx.session_id` is the run's target conversation. `day_open` is refused.
- **What she is told:** the scheduled overlay, the routine's request, its notes ("Follow these notes from the user: ..."), and the recipe when the target is the day (`persona/day.py`, as `day.build` composes it). For an `'own'` routine: "Show what you found with one workspace_show (mode replace), then say one sentence. If nothing is worth the user's attention, call routine_nothing instead and say nothing."
- **A day routine never overwrites a day built by hand:** if today's day conversation already has a board, the run is skipped and logged as `skipped`, with no notice.
- **Saved:** the request is saved as a host message ("Routine: Monday revenue"), never as the user's words, and her reply as hers, in the target conversation. The board is saved as any board, and its widgets get `live` from the run's reads (live widgets), so they refresh while seen.
- **Nothing to report (AGT-6):** a tool `routine_nothing` (READ, category `routine`, offered only to routine runs) ends the run as `nothing`: no notice, the reply not saved, a log line. A run that shows no widgets and says nothing counts the same.
- **Ready:** a run that shows a board writes a `'ready'` notice: title "Your Monday revenue is ready" (or "Your day is ready"), and the conversation id to open. The door delivers it like any notice (VOI-17, SUR-9). The page shows it as a line with an Open button, and marks the conversation unread in the thread list until opened.
- **Missed and failed** work as for timed asks: more than an hour late is reported missed, a failure is reported once and never retried blind (AGT-8). After **3** failed runs in a row a routine pauses itself and the notice says so ("Monday revenue failed three times, so I've paused it").
- **Read means read (MEM-5):** what a routine run reads counts as outside, as in any unattended run.
- **Cost:** a run's usage is recorded with its target conversation, so the cost line includes it.

## Changing a routine (AGT-7)

- Offered in a routine's own conversation, and in the day conversation when a day routine exists (category `routine`).
- Two tools, as standing rules have (`tools/rules.py`): `routine_narrow` (`Risk.WRITE`, no card) and `routine_widen` (`Risk.IRREVERSIBLE`, a card), each `{"routine": id, "text": "..."}` appended to the notes.
- **Narrow** ("stop showing refunds", "less detail", "never mention X"): applied at once, recorded, and said back. Her label is not trusted: the text must pass the same `narrows()` check standing rules use, or it is refused with "this adds to the routine; use routine_widen".
- **Widen** (a new source, a new kind of thing to look at): a card.
- Never from a run nobody is watching, never from a tapped ask (via `"ask"` refuses it), and never after reading outside content in the same turn.
- The next run reads the notes.

## Settings

- The existing reminders section (Settings, Reminders) gains a "Routines" group: each routine's name, when it runs ("Weekdays at 8:00 am"), the next run, where it lands ("Your day" or its conversation, with an Open link), and Pause/Resume and Delete. Delete asks once.
- `GET /api/routines`, `POST /api/routines/{id}/pause`, `.../resume`, `DELETE /api/routines/{id}`; the user's own taps, judged as the user's.

## Prompt

Lines in `text.md` and `voice.md` (no em or en dashes): a routine is a timed ask with `routine` set; when the user asks for something built or shown regularly, set one up; in a routine's conversation, "stop", "never" or "less" is `routine_narrow`, anything new is `routine_widen`.

## Out of scope

- Agents with their own model and instructions (AGT-1, AGT-2).
- A "Run now" button.
- Routines that act (send, buy, change): a routine reads and shows.
- Notifications outside the app (a phone, email).

## Testing

- **Server:**
  - the migration (counts and checksums, as earlier migrations);
  - `ask_schedule` with `routine`: the card's words; `day` and `own`;
  - a run: `'own'` makes its conversation once and replaces its board each run; `'day'` fills today's day conversation, and is skipped when a board is already there;
  - the router: `via="routine"` allows the board tools only on its own conversation, refuses them anywhere else, refuses `day_open` and everything `via="schedule"` refuses;
  - `routine_nothing` ends the run with no notice; a board writes one `'ready'` notice;
  - three failures pause it, with one notice;
  - `routine_narrow` stands at once and refuses text that widens; `routine_widen` asks; both refused unattended, from an ask, or after an outside read;
  - the request saved as a host message; usage recorded;
  - the API: list, pause, resume, delete.
- **Web:** the ready line with Open; the unread mark until opened; the Routines group in Settings with pause, resume and delete.
- **Live** (the user's Claude preview): "every weekday at 8, build my day", approved, then run due now (a test clock or a near time): the day board is built while the page is closed, the ready line appears when the page opens, Open shows it; a routine with nothing to report sends nothing.
