# Your own words as the yes

**Date:** 2026-11-11 · **Requirements:** SPN-20, with SPN-2, SPN-14a, SPN-17, MEM-5 · **Builds on:** [who said yes](2026-11-07-speaker-identity.md)

## Why

Every gated action takes two turns: she proposes it, and the owner approves on a later turn (SPN-2). That second turn exists because the model chose the arguments, and the owner has to see them before they run. For some actions it adds nothing. When the owner says "keep this as a rule: never book anything before nine" and the rule she would keep is exactly those words, the second "yes" approves what the owner has just said. It is friction, and friction is how gates get turned off.

SPN-20 lets the owner's own words be the yes, only where three things hold at once and code checks every one:

1. **It is the owner.** A spoken turn in the enrolled owner's voice (SPN-14a): not typed, not a tap, not unsure, not a replay, and never with nobody enrolled.
2. **The arguments are the owner's words.** Every argument that says what the action does appears word for word in what the owner said on this turn, the committed transcript (VOI-15a). The model chose none of it.
3. **It can be taken back.** The action is soft underneath: a forgotten memory is kept and marked, a dropped rule can be kept again, a new rule can be dropped. `spend`, `send_email` and anything unrecoverable always keep the second turn.

If any of them fails, nothing changes: the card appears and the owner approves it as now. The worst case is the card the owner already gets.

## Decisions

1. **Off until the owner turns it on.** Settings → Your voice gets a switch, "Let my own words approve things I can undo", shown only once a voice is enrolled, off by default. It is a setting in the database (the `own_words` preference), never something the model can change, and it lives in the owner-only settings the deny floor already protects. It is on only when the stored value is exactly `true`; the route takes only a JSON boolean, refuses to turn it on with nobody enrolled (`not_enrolled`), and forgetting the voice turns it off, so a voice taught again starts with it off.
2. **Tools opt in, one by one.** `ToolDefinition` gains `own_words: tuple[str, ...] = ()`: the names of the arguments that must appear in the owner's words. Empty means the tool never takes this path. At launch:
   - `rule_keep`: `("text",)`. The rule is kept in the user's words already.
   - `rule_drop`: `("about",)`. Only when given `about`; dropping by `id` keeps the card, since an id is not something anyone says.
   - `memory_forget`: gains an optional `about` (words from the memory, the way `rule_drop` has it: exactly one current memory must match, or nothing is forgotten and she asks which). `("about",)`. Forgetting by `id` keeps the card.
3. **The registry holds the line, not each tool.** At registration a tool with `own_words` is refused unless it is first-party (`trillion.tools`, not a connector, MCP server, skill or plugin), its risk is `irreversible` (never `spend`), it is `recoverable`, and every name in `own_words` is a property of its input schema. A structure test lists the tools that opt in, so adding one is a reviewed change. `send_email`, calendar changes, Slack posts and every MCP tool can never opt in.
4. **"Word for word", defined.** Both sides are normalised the same way: Unicode NFKC, casefolded, curly quotes and apostrophes made straight, every run of characters that isn't a letter, digit or apostrophe becomes one space (an underscore is not a letter), an apostrophe at either end of a word is dropped (it is a quotation mark there: "'nine'" is "nine", "don't" stays), and the ends are trimmed. The argument matches when its normalised words appear as one unbroken run, on word boundaries, inside the normalised utterance. It must be at least 2 words and at least 8 characters. Every argument the tool lists must match, and any argument present that it does not list must be absent (`additionalProperties` is already false on these tools). Numbers are not rewritten ("nine" does not match "9"). When she rephrases, the card appears.
5. **What counts as the owner's words.** `ToolContext.heard`: the committed transcript of this turn's spoken input (what the screen shows and the history keeps, a used draft's words included), set by the session from the speech-to-text result and never from anything the model says. None on a typed turn, a tap, a host turn (the turn a card's tap or a background read starts, even with the spoken turn's number), a channel message, a timed ask or a routine. A correction that lands mid-reply (VOI-16) is a new turn, not a change to this one's `heard`.
6. **Nothing from outside on that turn.** If the turn has read anything from outside (`ctx.read_outside`: a web page, a file, an email, a tool result marked untrusted), the path is closed and the card appears. Recalled memories don't close it, since they are "what was said" (MEM-5) and the argument still has to be in the owner's words. A helper's chat or run never takes it.
7. **One pure check.** `spine/confirm.py:own_words(definition, args, ctx, enabled) -> Rejection | None` takes no I/O, so every combination is tested exhaustively. It returns why not (`own_words_off`, `not_spoken`, `not_owner`, `read_outside`, `not_eligible`, `not_verbatim`) or None, asked in that order. A helper's chat or a routine's run is `not_eligible`. The reasons are logged by code only, never with the words, and not said to her: the fallback is the ordinary card.
8. **Same record, same checks.** On a yes from `own_words`, the router does everything the two-turn path does, in the same order. The call is checked as any call is (schema, deny floor, precheck), proposed as any gated call is (`PendingAction`, a `proposed` decision, its audit row), then given a decision with `event = "approved"` (the event every yes records), `decided_by = "own_words"`, `via = "voice"`, and run through the confirmed path: the deny floor again, the precondition and its fingerprint (SPN-2c), the one execution claim with the action's id as its idempotency key (SPN-17b) and the outcome (SPN-17a). What is skipped is waiting for a later turn and, with it, the card having been on a screen first (#4): the owner said what it does. A precheck that fails before the proposal (two rules match `about`) is refused as today, and she asks which. The decision record and Settings → Confirmations show it as "approved by your words", so "did I approve that?" is answered the same way as every other action.
9. **She tells the owner, and the screen shows it.** A card appears already resolved, saying what was done and "on your word", with the same detail as any card. She says it in a sentence ("Done, that rule is kept."), from the tool result, never from stock speech (PER-11). Undoing is the tool's opposite (`rule_drop`, `rule_keep`, or restoring a memory on the Memories screen), asked for like anything else.
10. **One per turn.** At most one action per turn takes this path. A second gated call in the same turn gets a card, so one long sentence can't approve a batch.

## What the user sees

- Settings → Your voice, once a voice is enrolled: "Let my own words approve things I can undo", off. Under it: "When you say exactly what to keep, drop or forget, she does it without asking again. Only for things that can be undone, and only in your voice. Spending, sending and anything that can't be undone always ask."
- With it on: "Keep a rule: never book anything before nine." She keeps it at once, says so, and a resolved card shows "Kept a standing rule: never book anything before nine. On your word."
- "Forget the memory about the dentist on Tuesday." If one memory matches, it is forgotten the same way. If two do, she asks which.
- She rephrases, it was typed, or she read a web page or a file this turn: the usual card, as now. A guest or an unsure voice gets what it gets today: nothing personal runs for it (PER-13), so not even a card.

## How

- `spine/contract.py`: `ToolDefinition.own_words`; `ToolContext.heard`.
- `spine/confirm.py`: `own_words(...)`, the normaliser and the matcher, and the new reasons.
- `spine/registry.py`: the rules in decision 3.
- `spine/router.py`: on a gated call, ask `own_words`; on None, record, decide and run through the confirmed path, one per turn.
- `tools/rules.py`, `tools/memory.py`: `own_words` on `rule_keep`, `rule_drop` and `memory_forget`; `about` on `memory_forget`.
- `api/session.py`: set `heard` from the committed transcript on spoken turns.
- The setting: stored with the other owner settings, read by the router through the runtime, and an `own_words` field on `GET`/`PUT /api/voiceprint`. `apps/web/src/voiceprint.ts`: the switch.
- The decision record and Confirmations view: show `decided_by = "own_words"` as "approved by your words".
- `SECURITY.md`: one paragraph on what this trusts (the speaker check, the transcript) and what it doesn't protect against beyond §5.3a's list: a speech-to-text mistake that happens to produce words that make sense is approved as heard, which is why only things that can be undone qualify.

## Tests

- `tests/spine/test_own_words.py`: the pure check, exhaustively: every speaker verdict, every `via`, `read_outside`, the setting off, a helper, each non-eligible tool, and the matcher (case, punctuation, curly quotes, word boundaries, "nine" against "9", too short, an argument missing from the words, one extra word in the middle).
- `tests/spine/test_own_words_router.py`: the whole path with a fake tool: the decision row (`own_words`, `voice`), the deny floor still refusing, a failed precondition, a second gated call in the same turn getting a card, and the idempotency key.
- A structure test: the opted-in tools, exactly; a connector, MCP or `spend` tool with `own_words` is refused at registration; `send_email` never has it.
- `tests/api/test_own_words.py`: a spoken turn with a fake embedder and transcript, keeping a rule in one turn; the same with the switch off, typed, rephrased, after a `file_read` this turn, and on the turn a card's tap starts, each getting the card; a guest's voice and an unsure one keeping nothing (PER-13). The switch on `/api/voiceprint`: off by default, needs a voice and a boolean, and goes off when the voice is forgotten.
- `apps/web/test/voiceprint.test.ts`: the switch, hidden with nobody enrolled.

## Not now

- Typed instructions as the yes. A typed message is the session's, not a verified person's; it keeps two turns.
- Undo on the resolved card.
- More tools (creating a file, timed asks). Each one is a reviewed opt-in, once its arguments can be said word for word.
- Matching numbers and dates said differently ("nine" and "9").
- A `how` of its own in the rules' history (`rule_events`). A rule kept or dropped on the owner's words is recorded there as `card`, the only other value its check allows; the decision record says `own_words`.
